Predict before you run.

TraceFirst is a first-year C++ tracer built on one rule: you never run code you have not first predicted. Commit to an answer, then step through the program and watch memory change. When your prediction and the machine disagree, TraceFirst stops at the exact statement where the two parted — and names the idea to fix.

Stage 1
Predict
Read the code. Say what it will print. Lock it in.
Stage 2
Run
Step line by line. Watch each variable's box change.
Stage 3
Investigate
Compare your answer with the machine's. Find the parting line.
Stage 4
Modify
One value changes. Predict again, from your repaired model.
Your field — same code, your world

Every field runs the identical program with the identical numbers. Only the story changes — so a class of mixed majors can argue about one answer together.

    How TraceFirst works: each exercise follows PRIMM — Predict, Run, Investigate, Modify — a sequence from computing-education research. The prediction is not a quiz before the lesson; it is the lesson, because the step-through that follows is read against a model you have already committed to. The four field skins share one code path and one set of numbers, so mixed-major classes discuss the same machine behaviour in four different worlds.
    
      
    

      
    
        
    
          
    Find the bugs. Classify them. Then prove the fix.
    
          
    Five short programs, broken on purpose — the first three from a debugging and code-reading lab built for a first-year introductory C++ course serving CS and non-CS majors together, the last two extending the same hunt to loops, arrays, and functions. Click a line to accuse it of being a bug. Every accusation that lands must then be classified, because the distinction this gym trains is the one beginners blur:
    
          
    
            
    Syntax errorThe code breaks a rule of the language. The compiler catches it and the program never runs.
    
            
    Logic errorThe code is legal, compiles clean, and still does the wrong thing. Only the output exposes it.

    Read the error. It is telling you where to look.
    
          
    A compiler message is not a verdict. It is a note from the program that checks your code, written in shorthand. Pick the error you just hit, or search for a word in it, and TraceFirst will translate it into plain English: what it means, what in your code causes it, and how to fix it.

    Tasks, projects, and an exam — at your level.
    
          
    Pick a level and work in three parts: short tasks checked instantly, guided projects with milestones and a prediction-first test bench, and a six-question exam scored at the end. Start where you are honest, not where you wish you were — the levels share ideas, so finishing one prepares the next.
    
        
    
        
    
        
    
          
    
        
    
        
    Tasks
    
        
    Six short exercises. Predict an output, complete a missing line, or spot a bug and its fix. Every answer is checked the moment you commit to it.
    
        
    
        
    Projects
    
        
    Build each project in your own editor, ticking milestones as you go. At the test bench, predict the verdict before you reveal it — then mark your own program pass or fail.
    
        
    
        
    Exam
    
        
    Six questions, answered in order. Each answer locks and explains itself as you go; your score appears at the end.
