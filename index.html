Meet the Code · Before the tracer

Meet the Code: what a program's lines are

Bolt gave you the logic. This is the same logic wearing real C++ clothing. Read the program once, line by line, with the note beside each line. There is nothing to predict yet, and nothing to run.

#include <iostream>

→This line brings in the tools for printing to the screen and reading input. Almost every program you meet here starts with it.

using namespace std;

→This lets the program write cout instead of std::cout. It appears once, near the top.

int main() {

→Every program starts running here, at main. The { opens the body of the program.

int score = 25;

→A statement: it makes a box named score and puts 25 in it. The ; ends the statement, the way a full stop ends a sentence.

score = score + 5;

→This reads the value in the box, adds 5, and puts the answer back in the same box.

cout << score;

→cout sends a value to the screen. The << points the way the value flows: out of the program, onto the screen.

return 0;

→main hands 0 back to the computer to say: finished, and nothing went wrong.

}

→This } closes the body of main. Every { must have its }.

Three rules to carry into the tracer

  • A semicolon ends a statement.
  • Braces { } group lines into one block.
  • The tracer will show you the boxes. Predict what is in them before you run.

Meet Bolt — programming before the syntax gets heavy.

Bolt is a workshop robot who understands exactly four commands: move, turn left, pick up a battery cell, put one down. That is all he will ever know. Everything Bolt does — crossing the Workshop, harvesting a row of cells, feeling his way around crates — is built by combining those four commands with loops, decisions, and functions you define yourself.

The programs are written in real C++ shape: every command ends with a semicolon, blocks wear braces, and helpers are void functions. Nothing here is a toy language you will have to unlearn. When you move on to the Prediction Tracer, the syntax will already look familiar; only the ideas will be new.

Start here. This mode comes first on purpose: finish these eight worlds and you already think in sequences, loops, decisions, and functions. Then predict and trace real code in the Prediction Tracer, where the same logic wears full C++ syntax.

Bolt's command card

Commands — every one ends with ;

  • move(); — step one square the way Bolt is facing.
  • turnLeft(); — turn 90° to Bolt's left, staying on the same square.
  • pickCell(); — pick up one battery cell from the square Bolt is standing on.
  • putCell(); — put one cell from Bolt's bag down on his square.

Sensors — questions Bolt can ask

  • frontIsClear() — true when the square ahead is inside the Workshop and holds no crate.
  • cellsPresent() — true when a battery cell sits on Bolt's square.
  • Put ! in front to flip the answer: !frontIsClear() means “something is in the way.”

Patterns — decide, repeat, name

void turnRight() { turnLeft(); turnLeft(); turnLeft(); } while (frontIsClear()) { move(); } for (int i = 0; i < 3; i++) { pickCell(); }

Decide with if (cellsPresent()) { ... } else { ... }. Define a helper once with void name() { ... }, then call it anywhere with name();.

How Bolt's World fits: this mode teaches the logic of programming — sequence, repetition, decisions, decomposition — inside a world small enough to see whole.     Find the bugs. Classify them. Then prove the fix.
    
          
    Five short programs, broken on purpose — the first three from a debugging and code-reading lab built for a first-year introductory C++ course serving CS and non-CS majors together, the last two extending the same hunt to loops, arrays, and functions. Click a line to accuse it of being a bug. Every accusation that lands must then be classified, because the distinction this gym trains is the one beginners blur:
    
          
    
            
    Syntax errorThe code breaks a rule of the language. The compiler catches it and the program never runs.
    
            
    Logic errorThe code is legal, compiles clean, and still does the wrong thing. Only the output exposes it.

      • 
              
    • Distinguish syntax from logic errors, with an example of each.
      • 
              
    • Point the stream operators the right way: << out with cout, >> in with cin — and say why main() returns int.
      • 
              
    • Explain operator precedence, the semicolon that detaches an if, and why text needs string and getline.

    Read the error. It is telling you where to look.
    
          
    A compiler message is not a verdict. It is a note from the program that checks your code, written in shorthand. Pick the error you just hit, or search for a word in it, and TraceFirst will translate it into plain English: what it means, what in your code causes it, and how to fix it.

    Prediction taught you to read the machine; this is where you write for it. Pick a prompt, write the whole program yourself in the editor, and run it right here. Then put it through the prompt's test bench: the machine runs your program once per test and compares what it prints with what the prompt asks for.
